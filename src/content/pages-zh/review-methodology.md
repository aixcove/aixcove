<p>AIX Cove 上的每一张工具卡片和每一篇对比文章，都遵循同一套编辑流程。本页说明我们如何调研、核验与更新内容——你可以据此自行判断我们结论的可信度。</p>

<h2>我们覆盖什么</h2>
<p>AIX Cove 发布三类内容：</p>
<ul>
<li><strong>工具档案（Listing）</strong>——单个 AI 工具的结构化画像：它是做什么的、擅长什么、怎么跑起来、有什么限制、与替代品的关系。</li>
<li><strong>横向对比（Comparison）</strong>——一对一对比页（如 Jules vs OpenHands），围绕工作流适配度展开，而不是功能清单打勾。</li>
<li><strong>指南与榜单（Guide / List）</strong>——面向特定任务、预算或部署形态的精选集合。</li>
</ul>

<h2>官方来源优先</h2>
<p>每一条事实性信息——定价、授权、平台支持、发布状态——都以厂商自己的材料为准：官方文档、定价页、changelog 和 GitHub 仓库。当官方来源互相矛盾、或厂商未发公告就调价时，我们会如实写明，而不是把数字取平均。第三方评测只作为辅助背景，绝不作为事实依据。每页底部列出本页引用的官方来源。</p>

<h2>能实测就实测，不能就明说</h2>
<p>只要公开试用、开源版本或免费额度允许，我们都会实际安装和使用工具——安装路径、CLI 手感、失败模式，恰恰是规格表上看不到的东西。当我们无法实测（封闭内测、仅企业版、成本超出合理预算），页面会明确写出。我们不编造没有过的第一手体验。</p>

<h2>我们检查什么</h2>
<ul>
<li><strong>身份与状态</strong>——开发方是谁、开源还是闭源、许可证、处于 GA / Beta 还是已停止维护。</li>
<li><strong>核心能力</strong>——工具真正能做什么，以文档核验为准，而非营销文案。</li>
<li><strong>定价</strong>——当前档位、免费额度、典型工作流的实际成本，并标注核验日期。</li>
<li><strong>部署与运维</strong>——安装步骤、平台要求、工具默认使用者应具备的运维知识。</li>
<li><strong>限制</strong>——厂商声明的约束、安全考量、可观察到的扩展性注意事项。</li>
<li><strong>生态定位</strong>——与哪些替代品直接竞争、各自适合谁。</li>
</ul>

<h2>对比文章怎么写</h2>
<p>对比页先给快速结论，再拆解真实差异：工作流、部署、定价、安全。结尾按角色给建议（"如果你是 X 就选 A，如果你要 Y 就选 B"），而不是硬凑一个唯一赢家——工具选择本质上取决于你的约束条件。</p>

<h2>更新与纠错</h2>
<p>AI 工具变化很快。定价与功能信息都带"核验于"日期；厂商发布重大版本后，对应页面会重新核查。如果你发现过期数字或错误事实，欢迎<a href="/zh/contact-us/">告诉我们</a>——纠错会很快上线，不会被悄悄掩埋。</p>

<h2>编辑标准</h2>
<ul>
<li>官方来源优先；营销说法要么核实、要么标注存疑。</li>
<li>不虚构测试；未经实测的结论明确标注。</li>
<li>无付费排名；精选（Featured）标记为编辑行为。</li>
<li>如未来引入联盟链接或赞助内容，将在页面内显式标注。</li>
</ul>
